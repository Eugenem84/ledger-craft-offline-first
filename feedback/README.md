# `feedback/` — инбокс отчётов об ошибках

Каталог для отчётов кнопки «Сообщить об ошибке» (Фаза 14, `docs/FEEDBACK.md`, решение D7).
Он существует потому, что **агент/разработчик читает файлы репозитория** — БД и мессенджеры для
этого не подходят.

```
feedback/
├── README.md      # этот файл (в git)
├── INBOX.md       # дайджест: свежие отчёты сверху (в .gitignore)
├── inbox/         # по файлу на отчёт: <дата>-<короткий-uuid>.md (в .gitignore)
└── DECISIONS.md   # журнал разбора: отчёт → задача / «не баг» + объяснение (в git)
```

## Как получить отчёты

```bash
# .env.local (в git не попадает):
#   VITE_API_URL=https://ledgercraft.dev.medovf2h.beget.tech/api
#   FEEDBACK_PULL_TOKEN=<токен выгрузки с сервера>

npm run feedback:pull                 # выгрузить новые отчёты → feedback/INBOX.md + feedback/inbox/*
npm run feedback:pull -- --all        # выгрузить все (не только новые)
npm run feedback:pull -- --file=~/Downloads/report.md   # положить отчёт, присланный вручную
npm run feedback:pull -- --check      # что в контуре ещё не разобрано (только чтение)
```

**Боевой контур** (тот же токен, другой адрес): `npm run feedback:pull -- --check
--api=https://ledgercraft.ru/api`. Курсор выгрузки — **свой у каждого контура**
(`feedback/.pulled.json` → `contours.<домен>`), поэтому выгрузка с dev и prod больше не
«съедает» отчёты друг друга (задача 14.31: так потерялся отчёт dev-контура от 18.09).

## Как закрыть разбор: статус в контуре

У отчёта в базе контура есть **статус разбора** (`new`/`read`/`accepted`/`rejected`) и заметка
«что сделано» (`resolution_note`). Их показывает домашний монитор (сервис `homestatus` →
приложение `home-monitor-app`, экран «Фитбек»): `new` там подписан как **«не разобран»**.
Поэтому разбор **не считается закрытым**, пока статус не проставлен в контуре — иначе монитор
годами показывает «не разобран» по уже исправленным отчётам.

```bash
# проставить статус и заметку «что сделано» (по полному id или его префиксу):
npm run feedback:pull -- --mark=accepted --uuid=c49749a4 --note="15.13/15.14, APK 1.13" --api=https://…
npm run feedback:pull -- --mark=rejected --uuid=66597e07 --note="не берём: иконка — нативный манифест"
npm run feedback:pull -- --mark=accepted --note="…"    # пометить всё, что выгружено этим запуском
```

Пишем той же ручкой, что документирована в `docs/FEEDBACK.md` §2.6 — `PATCH /api/feedback/{uuid_id}`
с pull-токеном (`X-Feedback-Token`). Заметка видна в мониторе в карточке отчёта (он отдаёт
последние 20 отчётов и обрезает заметку на 600 символах).

### Правило (задача 14.9)

1. Выгрузить (`npm run feedback:pull`), разобрать каждый отчёт и записать вердикт в
   `feedback/DECISIONS.md` (баг → задача в `TODO.md`; «не баг» → объяснение).
2. **Проставить статус в контуре** (`--mark=accepted|rejected`, при желании `read`) с короткой
   заметкой «что сделано». Регресс закрыть тестом; в коммите сослаться на файл отчёта.
3. Ни один отчёт не остаётся «в воздухе»: либо задача, либо объяснение, либо статус «не берём».
   Проверка одной командой — `npm run feedback:pull -- --check` по каждому контуру.

Фаза 14 реализована (задачи 14.1–14.7): отчёты копятся на устройстве в очереди
`feedback_reports` (офлайн-первый путь), уезжают на сервер ручкой `POST /api/feedback`
(идемпотентность по `uuid_id`) и выгружаются сюда командой выше — читать нужно `INBOX.md`.

Если сервера/сети нет вовсе, работает **ручной путь**: в приложении настройки (шестерёнка в
таббаре) → «поддержка» → «Сообщить об ошибке» → «копировать текст в буфер» (тот же «снимок для
поддержки», 12.5), а файл кладётся в `inbox/` через
`npm run feedback:pull -- --file=<путь>` — имя подставится само.

## Что делать с отчётами — см. «Правило (задача 14.9)» выше

Коротко: разобрать → записать вердикт в `DECISIONS.md` → **проставить статус в контуре**
(`--mark`) → закрыть регресс тестом. Правило зеркалит чек-лист 11.5 и не дублируется здесь,
чтобы был один источник правды.

Приватность: сырые отчёты и `INBOX.md` **не коммитим** (там логи и аккаунт), поэтому они в
`.gitignore`. В git живут только этот файл и `DECISIONS.md` — без персональных данных.
