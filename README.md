# Ledger Craft

**Система учёта работ и запчастей для мастерских** — offline-first приложение.
Один и тот же код собирается в мобильное приложение под Android (**Capacitor**)
и в веб-версию. Приложение должно работать без интернета, а при появлении сети —
синхронизироваться с сервером.

## Стек

| Слой             | Технология                                                                                                                                                               |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| UI / сборка      | Quasar 2 (Vue 3) + Pinia + vue-router (hash)                                                                                                                             |
| Мобильная сборка | **Capacitor**                                                                                                                                                            |
| Локальная БД     | Android — нативный SQLite (`@capacitor-community/sqlite`), браузер — sql.js (WASM) + localStorage/IndexedDB                                                              |
| Синхронизация    | собственный сервис на очереди операций (`operations`)                                                                                                                    |
| Сетевой слой     | axios                                                                                                                                                                    |
| Бэкенд           | Laravel (PHP) + PostgreSQL — код в отдельном репозитории **`LedgerCraftDocker03`** (лежит рядом, общий `.code-workspace`); канонический контракт — в нём (`docs/API.md`) |

## Связанные репозитории

| Репозиторий                            | Что это                           | Где канонические доки                                 |
| -------------------------------------- | --------------------------------- | ----------------------------------------------------- |
| `ledger-craft-offline-first-PS` (этот) | клиент: Quasar/Vue + локальная БД | `docs/` (локальная архитектура и схема)               |
| `LedgerCraftDocker03`                  | сервер: Laravel + PostgreSQL      | `docs/API.md` (контракт API), `docs/DB.md` (схема БД) |

Оба открываются вместе через `.code-workspace`.

## Офлайн и синхронизация

Всё, что меняется, пишется сначала в локальную БД и в очередь операций — приложение работает
без интернета. Синк стартует **фоном** после отрисовки приложения (boot-файл сеть не трогает),
повторяется по таймеру и сразу по возвращении сети; состояние видно в компактном индикаторе
в шапке («нет сети» / «синхронизация…» / «ошибка синка» / «не отправлено: N»), тап по нему —
ручная синхронизация. Вне `MainLayout` (карточка заказа, вход, 404) индикатор плавающий, внизу
слева. Подробности — `docs/ARCHITECTURE.md` §4 и `docs/FRONTEND.md` §5.

## Вход и безопасность

Синк работает под `auth:sanctum` (задача 3.10), поэтому клиенту нужен токен:
`POST /api/login` (email + пароль) выдаёт его, и `src/services/api.js` подставляет
`Authorization: Bearer …` в каждый запрос (токен читается в момент запроса — после
входа синк работает без перезагрузки). Первый вход требует сети, дальше приложение
работает офлайн.

После входа предлагается PIN-код (4–8 цифр) — **локальный замок** приложения: при
следующем запуске нужно ввести PIN. В хранилище лежит соль + SHA-256-хеш, не
открытый текст; это защита от чужого взгляда, а не криптозащита данных — владелец
данных определяется серверным токеном. Выйти можно на странице «Другие».

Состояние «требуется вход» показывает индикатор синка (`src/utils/syncStatusView.js`),
тап по нему ведёт на экран входа. Доступ к маршрутам проверяет
`src/router/authGuard.js` (`meta.requiredAuth`; публичный только `/login`).

## Регистрация и рабочие профили (Фаза 10)

Регистрация доступна из экрана входа (`/register`): email + пароль и выбор **1..N специализаций**.
Сервер создаёт пользователя вместе со специализациями, а клиент сразу материализует пресеты —
новый пользователь видит готовый каталог своей ниши. Один аккаунт может вести несколько
профилей («веломастер + аквариумист»): активный переключается в шапке, он меняет заказы,
клиентов и каталог. Термины UI («заказ», «запчасть», «модель техники») берутся из лексикона
профиля, акцентный цвет — из пресета, а состав разделов (склад/товары, аналитика, модели,
share-ссылка, идентификатор объекта) настраивается тумблерами в «Ещё»: выключенный раздел
пропадает из нижних вкладок, а прямой переход по URL на него уводит на доступный экран. В каталоге
кнопки «Начать с шаблона» нет: профиль создаётся из пресета сразу с готовым каталогом, а каталог в
UI только наполняется и правится. Подробности — `docs/PLAN.md` §Фаза 10 и `docs/FRONTEND.md` §9.

Фаза 12 уточнила правила профилей: добавить можно **только специализацию из доступного списка**
(она сразу получает пресет и каталог), а переименовать профиль или сменить ему пресет нельзя —
только переключить активный или добавить ещё одну нишу (кнопка в настройках открывает диалог с
выбором ниши). Отладочные инструменты (снимок окружения и синка, очередь операций, буфер логов,
счётчики таблиц, полный сброс и удаление локальной БД) собраны в секции «Режим разработчика»:
она включается тумблером в настройках и **доступна и в боевой сборке** — на телефоне нет консоли,
а логи иногда нужно снять. Панель подгружается лениво и не мешает обычной работе. Подробности —
`docs/FRONTEND.md` §10, `docs/UI.md` §5–6.

## Конфигурация

Настройки сборки живут в env-файлах (их подмешивает Quasar CLI в любом режиме —
dev/prod/capacitor), читает их `src/config.js`:

| Переменная      | Назначение                                                       | Значение по умолчанию                          |
| --------------- | ---------------------------------------------------------------- | ---------------------------------------------- |
| `VITE_API_URL`  | адрес Laravel API (база для axios)                               | `https://dev.medovf2h.beget.tech/api` (`.env`) |
| `VITE_USE_MOCK` | включить моки сетевого слоя; учитывается **только в dev-сборке** | `false`                                        |

Дефолты лежат в отслеживаемом `.env`; личные переопределения — в `.env.local`
(он в `.gitignore`), например `VITE_API_URL=http://localhost:8000/api`. URL сервера
меняется без правки кода.

Моки — отдельный DEV-слой `src/services/mockApi.js`: он подключается динамическим
импортом, и в production-сборке ветка вместе с JSON-моками вырезается (проверяется
grep'ом по `dist/spa` — чанка `mockApi-*.js` там быть не должно).

## Среды и выкат (dev-VPS → prod-VPS)

Развёрнуты **два контура**, и они не взаимозаменяемы:

| Контур       | Адрес API                                                     | Назначение                       | Данные                                                 |
| ------------ | ------------------------------------------------------------- | -------------------------------- | ------------------------------------------------------ |
| **dev-VPS**  | `https://dev.medovf2h.beget.tech/api`                         | обкатка новых фич, отладка синка | песочница: БД не жалко, можно снести и накатить заново |
| **prod-VPS** | `https://<prod-домен>/api` (домен ещё не выбран — TODO 11.12) | боевой контур мастерских         | реальные данные: только бэкап + проверенное обновление |

Правило простое: **фича сначала обкатывается на dev**, проверяется по чек-листу (TODO 11.5) и только
потом уходит в бой (TODO 11.12). Код один и тот же — сборки различаются только адресом API.
Серверная сторона (домены, Traefik, CORS, команды выката, грабли) — канонически в
`LedgerCraftDocker03/docs/ENVIRONMENTS.md`.

### Как клиент попадает на контур

Адрес API нигде не зашит в код: он берётся из env-файла (задача 7.1), поэтому «переключить контур» —
это правка env, а не релиз:

| Файл                            | Когда читается                      | Назначение                                                     |
| ------------------------------- | ----------------------------------- | -------------------------------------------------------------- |
| `.env` (в git)                  | всегда                              | дефолт — адрес dev-контура                                     |
| `.env.local` (в `.gitignore`)   | всегда                              | личные переопределения (например, `http://localhost:8000/api`) |
| `.env.prod` / `.env.local.prod` | только прод-сборка (`quasar build`) | боевой адрес API                                               |

```bash
# разработка: клиент ходит на dev-VPS из .env
npm run dev            # http://localhost:9000

# dev-сборка статики
npm run build          # → dist/spa

# прод-сборка: положить рядом .env.prod (или .env.local.prod) с боевым адресом
#   VITE_API_URL=https://<prod-домен>/api
npm run build          # → dist/spa
```

### Как это проверяется на dev

На dev клиент удобнее всего держать **локально**: `npm run dev` поднимает его на
`http://localhost:9000`, и этот origin уже разрешён в `config/cors.php` бэкенда
(`allowed_origins`). SPA на VPS сейчас **не хостится** — `dist/spa` собирается тогда, когда
понадобится статика на хосте.

⚠️ **CORS**: если открыть клиент с другого origin (другой порт, `http://192.168.x.x:9000`,
размещённый SPA) — браузер заблокирует запросы к API, пока origin не добавлен в
`config/cors.php` на сервере. Признак: ошибка CORS в консоли браузера, при этом в логах Laravel
запроса нет.

`dist/spa` — статика с hash-роутером (`index.html`, `assets/`, `sql-wasm.wasm`).

## Мобильная сборка под Android

Локальная БД на Android — настоящий файл SQLite (`@capacitor-community/sqlite`), в браузере
остаётся sql.js. Адаптер выбирается автоматически по платформе (`Capacitor.isNativePlatform()`),
см. `docs/ARCHITECTURE.md` §4.5.

```bash
npx cap sync android                          # из src-capacitor: копирует веб-сборку и плагины
npx quasar build -m capacitor -T android      # сборка APK/AAB (нужны JDK + Android SDK)
npx quasar dev -m capacitor -T android        # запуск на устройстве/эмуляторе
```

> ⚠️ Папка `src-capacitor` в репозитории есть (манифест Capacitor + зависимости плагинов),
> там же лежит платформа Android (`src-capacitor/android`) с нашим плагином установки APK
> (`ApkInstallerPlugin`); на другой машине её поднимают командой `cd src-capacitor &&
npx cap add android` (⚠️ проверить, что платформа закоммичена — задача 13.10). Сборка и
> запуск возможны только на машине с JDK + Android SDK (в окружении, где писался код, их нет).
> `appId` (`com.ledgercraft.app`) стоит подтвердить до первого релиза: смена после публикации =
> новое приложение в магазине.

> 📱 **Системные панели Android.** С `targetSdk 35` (Android 15) система включает
> edge-to-edge **принудительно**, а Capacitor по умолчанию отступы не применяет: контент
> уезжал под статус-бар. В `src-capacitor/capacitor.config.json` стоит
> `android.adjustMarginsForEdgeToEdge: "auto"` — Capacitor сам добавляет margin высотой в
> системные панели (после правки прогнать `npx cap sync android`); тема `AppTheme.NoActionBar`
> в `src-capacitor/android/app/src/main/res/values/styles.xml` делает фон окна, статус-бар и
> навигационную панель чёрными со светлыми иконками. CSS `env(safe-area-inset-*)` на Android
> для статус-бара **не работает** — отступы верстать на него нельзя.

> 📶 **На телефоне «Нет связи с сервером», хотя интернет есть** — это почти всегда **CORS**, а не
> сеть: WebView отдаёт origin `https://localhost` (`androidScheme` в Capacitor по умолчанию
> `https`), и он должен быть в `allowed_origins` бэкенда (`config/cors.php`). Без него preflight
> `OPTIONS` уходит с `204` **без** `Access-Control-Allow-Origin`, и запрос блокируется ещё до
> Laravel — в логах сервера тишина. Проверено на живом dev-контуре 13.09.2026
> (подробности — `LedgerCraftDocker03/docs/ENVIRONMENTS.md` §2).

## Обновление Android-приложения (Фаза 13)

Приложение умеет обновлять себя **без Google Play**: сервер отдаёт актуальную версию,
приложение показывает чип «доступна версия N», а по кнопке скачивает APK и вызывает
системный установщик. Данные и настройки при этом сохраняются.

### Как это работает

```
сборка (npm run release:android)
   └─ APK на VPS + манифест releases.json  ←  php artisan app:publish-apk
        └─ GET /api/app-version  →  { versionCode, versionName, apkUrl, sha256, mandatory, notes }
             └─ приложение: versionCode меньше? → чип «доступна версия N»
                  └─ «Обновить»: скачали APK в кэш → сверили sha256 → системный диалог установки
```

- **`versionCode` — единственный критерий «новее»** (число), `versionName` — подпись для
  человека. Растёт `versionCode` в `src-capacitor/android/gradle.properties`
  (`APP_VERSION_CODE`); Android откажется ставить APK с меньшим или равным значением.
- **Подпись** — `keystore.properties` (в `.gitignore`), шаблон рядом:
  `src-capacitor/android/keystore.properties.example`. Ключ создаётся один раз и хранится
  в двух местах: **потеря ключа = невозможно обновить установленные приложения**.
- **`sha256`** из манифеста сверяется перед установкой: битый или подменённый файл не ставится.
- **`mandatory`** (или версия ниже `minSupportedVersionCode`) убирает кнопку «Позже», но
  офлайн-работа не блокируется — мастерская может продолжать работу без сети.
- На **Android 8+** система не покажет диалог установки, пока приложению не разрешена
  установка из неизвестных источников: приложение само отправляет на этот экран
  (`ApkInstaller.canInstall()` → `openSettings()`).

### Выпуск релиза

```bash
# 1. Поднять версию: src-capacitor/android/gradle.properties
#    APP_VERSION_CODE=3      # +1 к предыдущему
#    APP_VERSION_NAME=1.2

# 2. Собрать, подписать, выложить на dev-VPS и обновить манифест
RELEASE_SERVER=dev-vps npm run release:android -- --notes "Чиним склад"

# без сервера — только собрать (команды публикации скрипт напечатает)
npm run release:android -- --local-only

# обязательное обновление
npm run release:android -- --mandatory --min-version 2 --notes "Критичный фикс"
```

Скрипт: сборка web-части в режиме Capacitor → `npx cap sync android` → `assembleRelease` →
`apksigner verify` → `scp` на сервер → `php artisan app:publish-apk`. Правило сред обычное:
сначала **dev**, в prod — только проверенное (Фаза 11).

> **Ключ, toolchain и первый релиз (13.09.2026).** Ключ подписи — `~/keystores/ledger-craft-release.jks`
> (`CN=Ledger Craft`, RSA 2048), пароли — `src-capacitor/android/keystore.properties`; оба файла в
> `.gitignore`, `keystore.properties` указывает на абсолютный путь. **Сделайте копию ключа** (флешка,
> менеджер паролей): потеря = невозможно обновить установленные приложения.
> Для сборки локально нужны `JAVA_HOME=/opt/homebrew/opt/openjdk@21` и
> `ANDROID_HOME=$HOME/Library/Android/sdk` (`brew install openjdk@21` +
> `brew install --cask android-commandlinetools`, затем `sdkmanager "platform-tools"
> "platforms;android-35" "build-tools;35.0.0"`), `src-capacitor/android/local.properties` —
> `sdk.dir` в тот же путь. Первый релиз: **1.2 (versionCode 3)**, выложен на dev
> (`app:publish-apk`), `/api/app-version` отдаёт его с sha256, скачанный файл совпал с собранным.

> ⚠️ **Платформу `src-capacitor/android` нужно закоммитить.** Сейчас она локальная и git'ом не
> отслеживается (в ней `0` файлов), а с Фазы 13 там лежит наш код: `ApkInstallerPlugin.java`,
> `InstallResultReceiver.java`, `MainActivity.java`, настройка подписи в `build.gradle`,
> `gradle.properties` (версия) и манифест. Если папку не закоммитить, `npx cap add android`
> на другой машине создаст пустую платформу — кастомный плагин установки придётся писать заново.
> Исключения (уже в `.gitignore`): `keystore.properties`, `*.keystore`/`*.jks`, `app/build/`.

### Разрешение установки и «тихая» установка

Без Play или Device Owner (MDM) Android **всегда** показывает диалог подтверждения — это
не ограничение реализации, а защита системы. Тихо ставить умеет только Play (In-App Updates)
или владелец устройства.

⚠️ Если раздавать APK **через Google Play**, самообновление APK запрещено политикой
(«An app distributed via Google Play may not modify, replace, or update itself using any method
other than Google Play's update mechanism»), но обновление JavaScript внутри WebView —
разрешено («This restriction does not apply to code that runs in a virtual machine or an
interpreter… such as JavaScript in a webview»). Для Play-канала понадобится отдельный этап
(In-App Updates).

## Обратная связь: «Сообщить об ошибке» (Фаза 14 — реализовано)

Мастер работает на телефоне, где нет консоли разработчика. Кнопка **«Сообщить об ошибке»** (в «Ещё»)
работает **офлайн** и складывает отчёт туда, где его прочитает разработчик **и ИИ-агент**.
Агент читает файлы рабочего каталога — поэтому последнее звено цепочки это **инбокс в репозитории**,
а не БД, почта или мессенджер:

```
телефон (офлайн) → POST /api/feedback → feedback_reports на сервере
      → npm run feedback:pull → feedback/INBOX.md (+ feedback/inbox/*.md) → разбор
```

- Отчёт = текст мастера + диагностика: версия приложения, платформа, версия схемы, состояние синка,
  хвост ошибок и (по галочке) логи. **Данных мастерской в отчёте нет** (ни заказов, ни клиентов, ни
  сумм) — это закрыто тестом; отправка всегда по действию пользователя.
- Отчёт — **не** таблица синка (решение **D7**): «полный сброс»/бэкап его не тащат, второму
  устройству владельца он не приезжает, очередь у него своя (`feedback_reports`).
- Сегодня работает так: отчёт уходит на сервер и ждёт выгрузки; **аварийный путь** без сети/сервера —
  «копировать текст в буфер» в том же диалоге и `npm run feedback:pull -- --file=<путь>`
  (см. `feedback/README.md`).
- Команды: `npm run feedback:pull` (`--all`, `--file=<путь>`), токен выгрузки — `FEEDBACK_PULL_TOKEN`
  в `.env.local` (в git не попадает).

Контракт, приватность и приёмка — `docs/FEEDBACK.md`; задачи — `TODO.md` §«Фаза 14».
