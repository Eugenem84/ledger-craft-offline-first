# Интерфейс: дизайн-система Ledger Craft

Документ описывает, как устроен UI после переработки: **какие цвета за что отвечают**,
где живут токены, какие есть общие компоненты и по каким правилам собираются экраны.
Концепция и палитра сохранены: **чёрный фон + жёлтый акцент**, статусная светофорная
логика (ожидание / в работе / готово+оплачено), нижние вкладки, FAB.

> ⚠️ Это только представление. Логика (сторы, репозитории, синк, схема БД) не менялась.

## 1. Роли цвета

| Роль | Токен / цвет | Где применять |
|---|---|---|
| Фон приложения | `--lc-bg` (`#000`) | `body`, `q-page` (`.lc-page`) |
| Поверхности | `--lc-surface` / `--lc-surface-2` / `--lc-surface-3` | карточки `.lc-card`, шапка, таббар, диалоги |
| Границы | `--lc-border`, `--lc-border-strong` | разделители карточек и строк |
| Текст | `--lc-text`, `--lc-text-dim` (`.lc-muted`), `--lc-text-mute` (`.lc-mute`) | три уровня важности |
| **Интерактив (жёлтый)** | `$secondary: #ffeb3b`, `--lc-accent` | кнопки, вкладки, ссылки, фокус, FAB |
| **Акцент профиля** | `$primary` + runtime `setCssVar('primary', accent)` | только бейдж/иконка активного профиля |
| Статус: ожидает | `--lc-waiting` (`#ffb300`) | чип и полоса строки |
| Статус: в работе | `--lc-process` (`#e53935`) | чип и полоса строки |
| Статус: готово | `--lc-done` (`#43a047`) | чип и полоса строки |
| Оплачено | `--lc-paid` (зелёный) | отдельный чип рядом со статусом |

**Ключевое правило.** Жёлтый — это `secondary` и он **не меняется от профиля**.
`primary` — акцент рабочего профиля (пресеты: `#4caf50`, `#ff7043`, `#42a5f5`, `#26c6da`),
он подставляется в рантайме и используется только в бейдже профиля. Так фича «акцент по
специализации» видна, но не перекрашивает половину интерфейса.

Раньше: жёлтый был захардкожен в ~100 местах (`color="yellow"`, `bg-yellow`), а `primary`
переопределялся акцентом профиля → конфликт. Теперь и то и другое разведено по ролям.

## 2. Токены и утилиты

- `src/css/quasar.variables.scss` — палитра Quasar (`$primary`, `$secondary`, `$dark-page`, статусы).
- `src/css/app.scss` — CSS-переменные `--lc-*`, глобальные правки компонентов Quasar и утилиты:

| Класс | Смысл |
|---|---|
| `.lc-page` + `.lc-shell` | фон страницы и её отступы (по бокам — `--lc-pad-x`) |
| `.lc-card` | карточка-контейнер (границы, радиус, вложенные списки без двойных рамок) |
| `.lc-pad` / `.lc-pad-x` | внутренние отступы карточек и панелей (`--lc-pad-card`) |
| `.lc-eyebrow` | надзаголовок капсом (секции, лейблы) |
| `.lc-muted` / `.lc-mute` | вторичный / третичный текст |
| `.lc-money` | цифры (tabular-nums) |
| `.lc-status--waiting/process/done/paid/unknown` | чипы статусов |
| `.lc-order-row--waiting/process/done` | полоса статуса слева в списке заказов |
| `.lc-linerow`, `.lc-col-name/num/qty/del` | строки позиций (работы/материалы/товары). В строках показываются название, цена, **кол-во** и сумма: себестоимость из карточки заказа убрана (14.21), количество — целое ≥ 1 (14.19) и меняется шагомером «‹ N ›» (правка владельца 15.09.2026: `.lc-col-qty--stepper` — колонка под шагомер) |
| `.lc-stepper`, `.lc-stepper__btn`, `.lc-stepper__value` | шагомер количества: явные стрелки влево/вправо вокруг значения (правка владельца 15.09.2026) |
| `.lc-kpi`, `.lc-kpi__label`, `.lc-kpi__value` | плитки и цифры аналитики |
| `.lc-hide-sm` | прячет второстепенные колонки на экранах ≤ 420px |
| `.lc-fab` | позиция плавающей кнопки над таббаром (с учётом safe-area; не липнет к кромке — `right: max(…, 12px)`) |

Inline-стили в разметке не используются: цвет/размер берётся из токена или класса.

**Поля по краям экрана.** Боковое поле страницы — токен `--lc-pad-x`, внутреннее поле
карточек/строк — `--lc-pad-card`. Правка владельца 15.09.2026 («приложение слишком узкое»):
на телефоне боковое поле страницы — `0` (карточки во всю ширину экрана), внутреннее поле
карточки — `12px` (≤360px — `10px`); с `600px` оба возвращаются к `16px`. Раньше и страница,
и карточка добавляли по 16px, и контент уезжал от края на 32px — на узком экране блоки
выглядели «подвешенными». Внутренние панели вместо `q-pa-md`/`q-px-md` берут `.lc-pad`/`.lc-pad-x`.

## 3. Общие компоненты (`src/components/ui/`)

| Компонент | Зачем |
|---|---|
| `LcPageHeader.vue` | заголовок экрана (eyebrow + подпись + слот действий) |
| `LcSectionCard.vue` | секция-карточка (заголовок + содержимое) |
| `LcStatusChip.vue` | статус заказа: иконка + слово + цвет (слова из `ORDER_STATUSES`) |
| `LcEmptyState.vue` | пустое состояние: иконка, что произошло, что делать |
| `LcFab.vue` | кнопка основного действия на экране |
| `LcQuantityStepper.vue` | количество «‹ N ›»: явные стрелки влево/вправо (меньше/больше), целое ≥ 1; заменяет числовое поле с системными стрелками «вверх/вниз» |
| `LcDialogShell.vue` | оболочка диалога: заголовок, тело, «Отмена» + основное действие. Высота ограничена вьюпортом (`max-height: calc(100dvh - 32px)`), прокручивается только тело — длинный список внутри диалога не вылезает за экран (правка владельца 15.09.2026) |
| `AuthShell.vue` | каркас экранов `/login` и `/register` (бренд, QLayout + QPage) |

Правило: новый экран берёт готовые компоненты, а не рисует свои кнопки/секции/диалоги.

## 4. Каркас приложения

> ⚠️ **Ловушка Quasar:** `q-tab-panel` должен быть **прямым ребёнком** `q-tab-panels`.
> Quasar собирает список панелей из vnode'ов слота и сверяет их проп `name`
> (`quasar/src/composables/private.use-panel/use-panel.js` → `updatePanelsList`),
> а рендерит ровно одну панель (`getPanelContent()`). Если обернуть панель в свой
> компонент без проброса `name`, список панелей пуст и **содержимое всех вкладок
> не отрисовывается** — вкладки видны, а под ними пусто.
> Поэтому в карточке заказа `q-tab-panel` объявлены в `pages/OrderDetailsPage.vue`,
> а `OrderOverviewPanel` / `OrderServicesPanel` / `OrderMaterialsPanel` — это содержимое
> с обычным корнем `<div>`. Тест `test/order-tabs.test.js` следит за этим.

- `src/layouts/MainLayout.vue`: шапка с переключателем профиля, нижняя навигация.
  Состав вкладок — массив `tabs` (`v-for` + `class="col"`), видимость — флаги пресета
  (`useFeatures()`), подписи — лексикон (`useLexicon()`). При скрытии разделов сетка не «разъезжается».
- Таббар: `class="lc-tabbar"`, `padding-bottom: env(safe-area-inset-bottom)` для Android.
- **Системные панели Android.** Отступ под статус-бар задаёт Capacitor, а не CSS: в
  `src-capacitor/capacitor.config.json` стоит `android.adjustMarginsForEdgeToEdge: "auto"`
  (Android 15, `targetSdk 35` включает edge-to-edge принудительно; в Capacitor 8 это дефолт).
  Тема `AppTheme.NoActionBar` (`src-capacitor/android/app/src/main/res/values/styles.xml`,
  её ставит `BridgeActivity`) делает фон окна, статус-бар и навигационную панель чёрными,
  иконки — светлыми. `env(safe-area-inset-top)` на Android для статус-бара пуст, поэтому
  верстать отступы на него нельзя.
- `SyncStatusBar.vue` живёт в `App.vue` и виден на всех маршрутах, включая экраны входа.
- `OrderDetailsPage.vue` объявляет собственный `QLayout` + `QPage` (маршрут вне `MainLayout`);
  нижнего таббара у него нет, поэтому `LcFab` там не используется — создание позиции живёт
  в панелях вкладок (`OrderServicesPanel` / `OrderMaterialsPanel`).

## 5. Правила текста и доступности

- Подписи — строчными, полными словами: «ожидает», «в работе», «готово», «оплачено»
  (раньше — обрезки «ожид», «враб», «сохр», «опл»).
- Статус и оплата дублируются словом и цветом (не только цветом).
- Размер тап-зоны ≥ 40px (`.q-item` в `.lc-card` — ~52px), у иконочных кнопок — `round dense` + подсказка.
  Исключение — сегменты статуса/оплаты в шапке заказа: по правке живого прогона ряд сделан
  компактным (`dense` + `min-height: 28px`), чтобы шапка занимала меньше места.
- Деструктивные действия: красный/оранжевый цвет, подтверждение через `DeleteConfirmPage`.
  Полный сброс и удаление локальной БД (Фаза 12, 12.4/12.5) в пользовательских настройках
  **не показываются**, пока не включён тумблер «разработка»: тогда появляется панель
  «Режим разработчика» (`DeveloperPanel.vue`, вкладки «логи/диагностика/очередь/опасное»).
  Тумблер работает и в боевой сборке (флаг в `localStorage`), панель грузится лениво.
- Диалоги адаптивные (`max-width: min(92vw, 520px)`), вместо `min-width: 400px`,
  который вылезал за экран телефона. Высоту диалога ограничивает вьюпорт
  (`max-height: calc(100dvh - 32px)` в `LcDialogShell`), прокручивается только тело —
  иначе карточка с длинным списком (например, история склада товара) уезжала за пределы
  экрана, и до кнопок нельзя было добраться.
- Вкладки внутри раздела — `q-tabs` + `q-tab-panels`, панели **прямые дети**
  `q-tab-panels` (иначе Quasar не отрисует содержимое — ловушка в §4). Page-level
  действие (FAB) показывается только на «своей» вкладке (`v-if="tab === 'goods'"`).

## 6. Что проверять при изменениях UI

1. `npm run lint` и `npm test` — тест `test/pages-layout.test.js` следит за тем, чтобы
   `QPage` вне `MainLayout` был обёрнут в `QLayout` (иначе Quasar не монтирует страницу).
2. Проход по маршрутам: `/orders`, `/orders/new`, `/orders/:id`, `/store`, `/catalog`,
   `/analytic`, `/other`, `/login`, `/register`.
3. Смена профиля (bike/auto/hvac/aquarium): акцент бейджа, подписи лексикона, состав вкладок.
   Добавление профиля — только выбор из списка ниш; переименования/смены пресета у готового нет.
4. Узкий вьюпорт (360px): строки позиций, диалоги, шапка.
5. Индикатор синка (компактный чип в шапке): «требуется вход» / «нет сети» / «не отправлено: N».
6. Карточка заказа: статус и оплата — одним компактным рядом переключателей (`dense`,
   `min-height: 28px`), «оплачено» — таким же тумблером, без дублирующих чипов над ними;
   создание позиции — ровно одной кнопкой (в панели вкладки, FAB на странице нет).
7. Android (живое устройство): контент не уезжает под системные панели — отступы даёт
   Capacitor (`adjustMarginsForEdgeToEdge: "auto"`), полосы под статус-баром и навигацией чёрные.
8. Режим разработчика: тумблер «разработка» в «Ещё» показывает панель с вкладками
   «логи/диагностика/очередь/опасное» (работает и в prod-сборке — флаг в `localStorage`,
   панель — ленивый чанк); при выключенном тумблере секции нет.
